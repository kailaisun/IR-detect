# Multi-backbone infrared person-count classification

Binary classification of each 80×62 thermal-infrared pseudo-color PNG into
`one_person` or `two_people`. RGB is never used as model input. This document
compares six pretrained backbones under one identical recipe.

## Protocol

- Data: `person_count/dataset/{train,val,test}.csv`, generated by
  `person_count/prepare_dataset.py`.
- Splits are room-disjoint and match the detector benchmark:
  - train: rooms `01, 02, 04, 05, 06, 08, 09, 11, 12, 14, 15, 16, 17, 19`
    (58,704 images);
  - validation: `07, 13, 20` (12,282 images);
  - test: `03, 10, 18` (12,141 images).
- Input: 80×62 infrared pseudo-color PNG, aspect-ratio padded to 224×224.
- Loss: weighted cross-entropy; class weights are `one_person = 0.7413` and
  `two_people = 1.5360` (inverse-frequency, normalized).
- Optimizer: AdamW, learning rate `3e-4`, weight decay `1e-4`, cosine schedule.
- Batch size: 256 on one NVIDIA L40S, AMP mixed precision.
- Augmentation: horizontal flip, translation ±5%, scale 0.9–1.1.
- Selection: best validation macro F1; early stopping patience 6, maximum 30
  epochs.
- Test decision rule: `argmax` over the two class probabilities. No test-time
  threshold tuning is applied.

All six runs use this same recipe. The only difference is the pretrained
backbone and its final classification head.

## Key findings

1. **Swin-S is the best overall.** It has the highest accuracy, balanced
   accuracy, macro F1, two-person recall, and two-person ROC-AUC. Its advantage
   is concentrated in the harder two-person class.
2. **ConvNeXt-T is the best accuracy-versus-latency tradeoff.** It is close to
   Swin-S in accuracy but about 3× lower median batch-1 latency.
3. **Bigger is not automatically better here.** ConvNeXt-S slightly improves
   one-person recall but loses two-person recall relative to ConvNeXt-T on this
   small-resolution dataset.
4. **DINOv2 ViT-S underperforms under the shared recipe.** Its pretraining
   statistics are natural RGB images, and a fixed `lr=3e-4` full fine-tune is
   usually too aggressive for it. It likely needs a lower learning rate or a
   linear-probe-then-fine-tune schedule.

## Infrared-specific backbones

There is currently no widely adopted, plug-and-play "infrared-pretrained"
classification backbone with public weights that fits this task better than
ImageNet-pretrained models. The standard practice in thermal-infrared work is
to fine-tune a strong ImageNet/ImageNet-21k backbone, which is what this
document does. A possible future direction is self-supervised infrared
pretraining (for example on infrared image collections such as `InfMix`), but
that is not a ready-to-load baseline here.

## Reproduction

```bash
cd person_count

# Train one backbone (see timm/torchvision model names in summary.json).
python train.py --model <backbone_name> --output runs/<run_name> \
  --epochs 30 --batch-size 256 --workers 12 --patience 6 \
  --device cuda:0 --cache

# Evaluate the selected best checkpoint on the held-out test rooms.
python evaluate.py --checkpoint runs/<run_name>/best.pt \
  --output results/comparison/<run_name>/metrics.json \
  --batch-size 256 --workers 12 --device cuda:0 --cache

# Batch-1 latency benchmark.
python benchmark.py --checkpoint runs/<run_name>/best.pt \
  --output results/comparison/<run_name>/benchmark.json \
  --frames 1000 --warmup 100 --repeats 3 --device cuda:0
```

The training checkpoints are written under `runs/` and are intentionally
ignored by Git; only metrics and code are published.
